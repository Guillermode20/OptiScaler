# Native Async Timewarp — Plan

## Context

Convert OptiScaler's DX12 reprojection from its validated synchronous presentation path into genuine asynchronous timewarp that returns the game's `Present()` promptly while a dedicated presenter repeatedly warps the newest completed frame at display cadence. The implementation must remain native to OptiScaler, preserve safe swapchain/resource ownership on Windows and Proton, use rotational late-latching first, and fall back synchronously rather than showing black or racing game backbuffers when required presentation capabilities are unavailable.

**Implementation status (2026-08-23):** The virtual-swapchain ownership seam was live-validated in Deep Rock Galactic on Proton on 2026-08-22. The presenter has since been changed to one persistent display-clock loop: packet publication only replaces the anchor at a scheduled slot, every valid output (including a new anchor's first display) is warped, and async presentation is always `Present(1, 0)`. This revised cadence and the motion-grid calibration still require a fresh Windows build and DRG panning validation. Keep `ReprojAsync=false` as the shipped default.

The display-clock diagnostics separate renderer updates from actual display output. At a 30 FPS source on a 120 Hz display, the invariant is approximately 30 source updates and 120 total warped presents, divided into about 30 new-anchor displays and 90 repeated-anchor displays. Packet arrival never causes an extra present or restarts the display deadline.

When a game supplies projection values but no camera basis (the DRG path), late-latched mouse rotation uses an exact projection-space rotational homography. A 16x9 motion-vector grid is copied asynchronously from the packet-owned velocity texture and robustly fitted to yaw/pitch; accepted fits are regressed against raw input over 0-150 ms lag bins. `[Reproj] InputPoseLagMs=auto` uses that learned delay, while an explicit value overrides it. Until at least 24 frames and 70% confidence, the manual mouse scale and one-source-frame pose-lag estimate remain active.

Mouse-look rotation is detached from render cadence in this mode. Translation, independently animated world objects, recoil, head bob, and scripted camera effects still update only when the renderer publishes a new anchor.

Two implementation clarifications were required during review:

- DXGI RTVs are normally created after `GetBuffer`, so their sRGB intent is not reliably available while the virtual ring is created. The implementation preserves an already typed resource format and maps only fully typeless families to their UNORM member. HUDless comparisons use the same normalization.
- A D3D12 swapchain remains associated with its creation command queue even when `Present` is called from another thread. The worker therefore writes real buffers on its private queue, signals the presenter fence, and makes the creation/game queue wait on that fence before every raw present.

## Approach

### 1. Virtualize game-visible DX12 backbuffers in the existing swapchain wrapper

- Extend `WrappedIDXGISwapChain4` in `OptiScaler/wrapped/wrapped_swapchain.{h,cpp}`; do not add a second HWND, DirectComposition surface, or FFX presenter dependency. Keep its constructor signature unchanged so all existing non-reprojection construction callsites remain unchanged.
- Add an internal `VirtualBackBuffer` ring with exactly the real swapchain's buffer count (the reprojection creation path already forces at least `BUFFER_COUNT == 3`). Each entry owns one committed default-heap `ID3D12Resource`, a capture-fence reference/value, and state `Available`, `Rendering`, or `Capturing`.
- Add `bool InitializeReprojectionVirtualization()` and call it explicitly from `AReproj_Dx12::CreateSwapchain/CreateSwapchain1` after constructing the wrapper. It succeeds only when `ReprojAsync=true`, `_device` resolves to an `ID3D12CommandQueue`/`ID3D12Device`, the real swapchain is flip-model, and `IDXGISwapChain2::GetFrameLatencyWaitableObject()` returns a valid handle. Any failed condition leaves forwarding behavior unchanged and returns a wrapper around the real swapchain for the safe synchronous path.
- Create virtual textures from each real backbuffer's description with initial state `D3D12_RESOURCE_STATE_PRESENT`. Do not expose actual DXGI backbuffers to the game while virtualization is enabled. Preserve formats that DXGI already reports as typed. If a flip-model backbuffer is reported as fully typeless, map it deterministically to the family's `*_UNORM` member (including `R10G10B10A2_UNORM` for that HDR family), because the game's later RTV creation cannot be observed at ring-initialization time and D3D12 rejects `ALLOW_RENDER_TARGET` resources with a fully typeless format. Normalize the HUDless eligibility check with the same mapping so the UI-split path does not silently disable.
- While virtualized, populate `State::Instance().scBuffers` with the virtual ring resources instead of `_real->GetBuffer` results, because `ResTrack_Dx12` classifies captured resources by comparing against `scBuffers`; restore the real-buffer population when virtualization shuts down.
- Add exact public wrapper methods used only by reprojection:
  - `bool IsReprojectionVirtualized() const`
  - `HRESULT GetReprojectionBuffer(UINT index, REFIID riid, void** resource)`
  - `HRESULT SubmitReprojectionBuffer(UINT index, ID3D12Fence* captureFence, UINT64 captureFenceValue)`
  - `HRESULT AdvanceReprojectionBuffer()`
  - `void AbortReprojectionBuffer(UINT index)`
  - `IDXGISwapChain3* RealSwapChain3() const` (borrowed pointer; caller must not release)
  - `void ShutdownReprojectionVirtualization()` — drain capture fences, release the ring, restore plain forwarding and real-buffer `scBuffers` population; called from `AReproj_Dx12::DestroyFGContext`/`ReleaseSwapchain` so a deactivated feature never leaves the game presenting into a dead ring
- In `GetBuffer` and `GetCurrentBackBufferIndex`, return the virtual ring resource/logical index only while virtualized; otherwise retain current forwarding. The logical index advances only via `AdvanceReprojectionBuffer()`; the real swapchain's index advances only via worker presents, and no code may mix the two (the step 5 sync helper reads the real index only while the worker is stopped and drained). Presents carrying `DXGI_PRESENT_TEST` forward to the real swapchain for occlusion status without capturing, submitting, or advancing anything. `AReproj_Dx12::Present()` calls `AdvanceReprojectionBuffer()` before returning from every successful virtual-buffer submission because `FGHooks::HookFGSwapchain` detours the wrapper's `Present` vtable entry and therefore bypasses `WrappedIDXGISwapChain4::Present`.
- `AdvanceReprojectionBuffer()` waits only for the next virtual entry's capture fence (5-second timeout, matching existing allocator waits) under a dedicated mutex owner ID, with the fence wait performed outside `_localMutex` so a GPU stall cannot block unrelated game swapchain calls. Treat `GetCompletedValue() == UINT64_MAX` as device removal. On timeout it must not merely return an error for the caller to ignore (`FGHooks::FGPresent` returns `S_OK` to the game unconditionally for Reproj): log, mark the presenter degraded, and let the next `AReproj_Dx12::Present()` perform the step 4 downgrade to the synchronous path so a wedged ring can never wedge the game.
- `SubmitReprojectionBuffer()` validates the current index/state, AddRefs the fence, stores its value, and marks the entry `Capturing`. `AdvanceReprojectionBuffer()` releases that fence after completion. `AbortReprojectionBuffer()` is legal only before submission and leaves the current entry renderable.
- Apply identical virtualization handling to `ResizeBuffers` and `ResizeBuffers1`: the existing `FGHooks` resize path first deactivates/joins reprojection; wrapper resize then waits capture fences, probes each virtual resource with `AddRef/Release` and returns `DXGI_ERROR_INVALID_CALL` if its post-probe count exceeds the wrapper's sole reference, releases the ring, resizes the real swapchain, recreates virtualization, and re-applies maximum frame latency plus re-caches the waitable handle (the handle survives `ResizeBuffers`, but re-query it rather than reuse). Destructor performs the same drain-before-release ordering. In `FGHooks::hkFGRelease`, detect the reprojection wrapper and skip the legacy loop that forcibly releases `GetBuffer()` references; teardown must let wrapper ownership release virtual resources normally.

### 2. Make the main real swapchain worker-presentable

- In `AReproj_Dx12::CreateSwapchain` and `CreateSwapchain1`, when `ReprojAsync=true`, request `DXGI_SWAP_CHAIN_FLAG_FRAME_LATENCY_WAITABLE_OBJECT | DXGI_SWAP_CHAIN_FLAG_ALLOW_TEARING`, at least three buffers, and a flip-model swap effect. Preserve the existing real factory/queue unwrapping. The real waitable handle is worker-exclusive: extend `FGHooks::hkGetFrameLatencyWaitableObject` so Reproj output behaves like the existing XeFG path and hands the game a duplicated semaphore instead of the real auto-reset event. Two waiters on one frame-latency event steal each other's signals, so the game must never hold the real handle while the worker waits on it.
- If creation with the waitable flag fails, retry once with the original flags plus the existing synchronous reprojection requirements; store async capability as false and log `Reproj: waitable main swapchain unavailable ({:X}); using safe synchronous presenter`. Do not fail game swapchain creation merely because async capability is missing.
- On successful raw DXGI creation, retain an explicit `_swapChain` reference to that actual HWND swapchain, construct `WrappedIDXGISwapChain4(rawSwapChain, realQueue, hwnd, flags, false)`, call `InitializeReprojectionVirtualization()`, return the wrapper to the game, and set `State::Instance().currentWrappedSwapchain` to it. `FGHooks::SetFGSwapchain` then stores/hooks that wrapper. Query the raw swapchain as `IDXGISwapChain2`, set maximum frame latency to `1`, and retain its waitable handle only when virtualization initialized. Release ordering is wrapper/game reference first, AReproj's explicit raw reference second; avoid the current raw-pointer double-release path. Note the wrapper constructor takes its own reference on the real swapchain, so AReproj's stored raw pointer requires its own matching `Release()` and must not be treated as ownership transferred to the wrapper.
- Track `ReprojAsync` transitions in `EvaluateState`; changing it sets both `State::Instance().fgChanged` and `scChanged` because a raw swapchain cannot be converted safely in place. A live swapchain cannot gain `FRAME_LATENCY_WAITABLE_OBJECT` in place either, so the toggle takes effect only when the game recreates its swapchain; log that expectation once at transition time so a seemingly inert setting is explainable.

### 3. Replace the DComp/secondary-HWND presenter with the real-swapchain worker

- Delete `ReprojPresenterWindowClass`, `ReprojPresenterWindowProc`, `<dcomp.h>`, the DComp pragma/library dependency, `_presentSwapChain`, `_presentHwnd`, `State::Instance().reprojPresenterHwnd`, all `_composition*` members, `_presenterUsesComposition`, `_presenterAttached`, `EnsurePresenterAttached()`, and every show/hide/child-window branch. No compatibility alias or dormant fallback remains.
- Keep the existing `_presentQueue`, packet ring, `_presentThread`, `_presentCv`, `PresenterState`, `_uiFence`, `_scFence`, `DrainGpuWork()`, `WaitForSCAllocator()`, and packet transitions. They already encode the required `FREE -> CAPTURING -> READY -> PRESENTING -> RETIRED -> FREE` ownership.
- Rewrite `CreateAsyncPresenter()` to succeed only when `State::Instance().currentWrappedSwapchain` is the same game-facing object as `currentFGSwapchain`, its known concrete `WrappedIDXGISwapChain4*` reports `IsReprojectionVirtualized()`, `_swapChain` equals `RealSwapChain3()`, the waitable handle exists, and the dedicated direct `_presentQueue` is created. Do not use `QueryInterface` to recover the concrete C++ class: it has no custom IID. Recover it with a `static_cast` from the stored `IDXGISwapChain*`, which is valid only because the class is `final` with a single inheritance chain; raw-pointer equality between `_swapChain` (`IDXGISwapChain*`) and `RealSwapChain3()` (`IDXGISwapChain3*`) holds because both QIs resolve to the same non-aggregated object. Failure returns false before a worker starts, leaving the wrapper usable by the synchronous copy path.
- Change `DisplayPacket`, `DispatchPacketWarp`, and `PresentCompositorFrame` to target raw `_swapChain`, presented directly: the present detour lives on the wrapper's vtable, not the raw one, so `SkipPresent` is unnecessary there; call `fakenvapi::reportFGPresent` explicitly with the raw pointer and verify fakenvapi tolerates a swapchain pointer it did not see created. `PresentCompositorFrame` waits with a bounded timeout on the worker-exclusive latency handle before every actual present, and adds `DXGI_PRESENT_DO_NOT_WAIT` only when `syncInterval == 0` — the flag is invalid with vsync intervals and would fail every anchor present with `E_INVALIDARG`. Preserve the packet's real-frame sync interval/flags for anchors; generated frames use interval `0` and tearing only when `SCAllowTearing && !realExclusiveFullscreen`; `DXGI_ERROR_WAS_STILL_DRAWING` drops that output without failing the presenter.
- `PresenterMain` is one persistent display-clock loop. It waits for a display slot, chooses the newest completed packet immediately before dispatch, warps even the first display of that anchor, and issues exactly one `Present(1, 0)`. Packet publication cannot present or reset the deadline. Superseded packets retire only after capture and presentation fences complete; a missed deadline advances to the next future slot without a catch-up burst.
- Add `syncInterval` and `presentFlags` to `ReprojFramePacket`; populate them on the game thread from `FGHooks::LastPresentSyncInterval()`/`LastPresentFlags()` and consume only the packet copies on the worker. This removes the existing unsynchronized worker reads of global present arguments.
- A worker error sets `PresenterState::Failed` and wakes the game thread. On its next `Present()`, stop/join worker, drain both fences, destroy presenter queue state, then continue through the synchronous virtual-buffer path. The downgrade is permanent for the session (log once); do not auto-restart the worker, so transient GPU stalls cannot thrash thread/queue teardown. Every worker-side wait (latency handle, allocator fences, `WaitForPacketDeadline`) must be bounded so the join cannot hang. Never call back into swapchain resize/destruction from the worker.

### 4. Publish self-contained frame packets from virtual backbuffers

- Change the private signature to `bool CaptureFramePacket(int sourceIndex, int packetIndex, ID3D12Resource* gameBackBuffer, UINT virtualBufferIndex)`.
- While the worker is Running, EVERY frame publishes a packet — including reset frames, missing velocity, stale pose, and focus-lost — as a warp-suppressed packet (`warpAllowed = false`, consumed by `DispatchPacketWarp` to skip warping and present only the anchor). The game thread may never touch real presents while the worker owns them; two threads presenting one swapchain across two queues without cross-queue fences corrupts output. In async `AReproj_Dx12::Present()`, use the known `State::Instance().currentWrappedSwapchain` concrete pointer after verifying object identity with `currentFGSwapchain`, get its current virtual buffer, acquire a packet, and copy color/HUDless color, velocity, optional depth, and optional UI with existing `CopyPacketResource`, `FillConstants`, `SubmitUICommandList`, and `_uiAllocatorFenceValues`. Do not read `_swapChain->GetBuffer()` here; those are presenter-owned real buffers.
- After successful packet capture, call `SubmitReprojectionBuffer(virtualBufferIndex, _uiFence, packet.captureFenceValue)`, set packet timestamps/present arguments, publish `Ready`, notify `_presentCv`, call `AdvanceReprojectionBuffer()`, and return without calling real DXGI `Present()`.
- If no packet is free, wait on `_presentCv` for at most two target-refresh periods for retirement or presenter failure; this is bounded backpressure, doubles as the game's pacing mechanism in async mode, and contributes to `gamePresentBlockMs`. Packet starvation alone never tears down the worker: on timeout drop this frame's publication and let the worker keep displaying/warping its newest ready packet. Only capture failure, wrapper submission failure, or an `AdvanceReprojectionBuffer()` timeout downgrades to synchronous: stop/join the worker (permanent for the session), signal-wait a `_presentQueue` fence so game-queue writes to real backbuffers never race retired worker submissions, then run the synchronous virtual-anchor helper from step 5, submit the virtual buffer with the helper's game-queue fence, and advance it.
- Maintain frame cadence internally from `RecordRealFrame` timestamps for `packet.frameDelta` and warp `timeStep` math instead of reading `State::Instance().lastFGFrameTime`, which stops updating once `LocalPresent` is bypassed by the virtualized present path.
- Keep packet resources private and reusable only after both capture and presenter retirement fences complete. Virtual game buffers require only the capture fence because packet copies sever their lifetime from the game surface; wrapper backpressure therefore never waits for display presentation.

### 5. Preserve a correct synchronous/pass-through path

- Refactor `CopyLastFrame` into `bool CopyLastFrame(int fIndex, ID3D12Resource* source)` and add `HRESULT PresentVirtualFrameSync(int fIndex, ID3D12Resource* source, UINT virtualBufferIndex, UINT syncInterval, UINT flags)`.
- `PresentVirtualFrameSync` is legal only when the presenter is fully stopped and GPU-drained. It copies the virtual source into `_lastColor`, submits on `_gameCommandQueue`, calls `SubmitReprojectionBuffer` with that copy fence, copies the real anchor into raw `_swapChain`'s current backbuffer (reading the REAL index, which is stable precisely because the worker is stopped), and performs the actual `PresentFrame`. If reprojection is active, retain existing bounded synchronous warp scheduling after the real anchor; if inactive/paused/reset/missing velocity/stale pose/focus-lost, present only the unwarped anchor.
- Route every virtualized `Present()` branch through either async packet publication or `PresentVirtualFrameSync`; the current early inactive/paused branch must not directly present an untouched real backbuffer. This includes the hook layer: `FGHooks::FGPresent`'s inactive/paused pass-through branch falls through to `o_FGSCPresent`, which under virtualization would real-present a backbuffer nobody rendered into, so it must divert to the anchor path while virtualized. When virtualization is unavailable, retain the existing raw-backbuffer synchronous logic unchanged.
- A reset frame or missing velocity publishes no warp but still presents the newest real virtual frame. Device removal is logged via `GetDeviceRemovedReason` and triggers the synchronous downgrade rather than being propagated to the game (`FGHooks::FGPresent` returns `S_OK` unconditionally for Reproj); occlusion pauses warp production without marking the presenter permanently failed.

### 6. Keep late-latched rotational warp and UI behavior at presentation time

- Reuse `FillConstants`, `ApplyLateLatch`, `OptiInput::GetRawMouseMotionAt`, `ReprojRotationOnly`, manual mouse scales, and auto-calibration. Keep late-latch sampling inside `DispatchPacketWarp`, immediately before the worker records each warp; never move it back to packet capture.
- Reuse packet HUDless/UI selection and `RUI_Dx12`: warp HUDless color when both HUDless and UI resources are ready, then composite unwarped UI onto each generated real-swapchain backbuffer. Otherwise warp the complete frame and report `hudWarped=true`.
- Version 1 remains rotational/MV/depth behavior already implemented; do not add translation prediction, new calibration, optical flow, Vulkan, or DX11 while changing presentation ownership.

### 7. Make async state observable and truthful

- Change `RuntimeMetrics::asyncPresenter` meaning to “main swapchain is virtualized and worker owns real presents.” Add `float gamePresentBlockMs` measured around the game-facing enqueue/copy path, not around worker presentation.
- Change log presenter literal from `async waitable flip`/`async flip` to `async virtual swapchain`; retain `safe sync`. Emit one activation line exactly: `Reproj: activated (async virtual swapchain)` or `Reproj: activated (synchronous)`.
- Update `OptiScaler/menu/menu_common.cpp` async help/status strings to describe virtual game backbuffers plus worker-owned main swapchain, and display game-present block time beside queue depth. Remove all claims about DirectComposition.
- Update the behavior-defining comments for `Config::ReprojAsync` and `ReprojMaxWarpFrames` in `OptiScaler/Config.h` plus `[FrameGen] FGOutput=asynctimewarp`/`[Reproj] Async` text in `OptiScaler.ini`: `Async=true` requests main-swapchain virtualization and falls back synchronously when unavailable; `MaxWarpFrames` caps worker warps in async mode and blocking warps in synchronous mode.
- Update the design docs that currently forbid this architecture: the `AGENTS.md` invariant ("Never point the worker at the game's DXGI backbuffers") must be rewritten around the new one — the worker owns real backbuffers precisely because the game no longer renders into them — and `AsyncReprojection.md` / `AsyncReprojection_Continuation_Plan.md` need a superseding note describing virtualized-backbuffer presentation instead of DirectComposition.
- Record the initial validation result: Deep Rock Galactic on Proton live-validated the async path on 2026-08-22. Keep the matrix otherwise sparse until more games are tested.

## Amendment notes (review round 1)

Changes made after a code-level review against `wrapped_swapchain.{h,cpp}`, `AReproj_Dx12.{h,cpp}`, and `FG_Hooks.{h,cpp}`:

1. **Virtual-texture format** — flip-model backbuffer descs are fully typeless and D3D12 rejects typeless + `ALLOW_RENDER_TARGET`; added typed-format family mapping (sRGB vs UNORM vs HDR) and normalization of the HUDless format check in `CaptureFramePacket`.
2. **Latency-handle exclusivity** — the real waitable event is worker-only; the game receives a hooked duplicated semaphore via `hkGetFrameLatencyWaitableObject` (XeFG-style), preventing two waiters from stealing each other's signals.
3. **`DXGI_PRESENT_DO_NOT_WAIT` gating** — only valid with `SyncInterval == 0`; unconditional use would fail every vsync anchor present with `E_INVALIDARG`.
4. **Single-presenter invariant** — reset/stale/focus-lost frames publish warp-suppressed packets while the worker runs; `PresentVirtualFrameSync` is gated to a stopped-and-drained presenter with a present-queue fence handoff for cross-queue backbuffer ownership.
5. **Ring recovery** — an `AdvanceReprojectionBuffer()` timeout now downgrades to the synchronous path instead of returning an HRESULT that `FGPresent` swallows; `GetCompletedValue() == UINT64_MAX` treated as device removal.
6. **`DXGI_PRESENT_TEST`** — forwarded to the real swapchain without capturing, submitting, or advancing the ring.
7. **Hook-layer routing & teardown** — `FGPresent`'s inactive pass-through branch diverts while virtualized; added `ShutdownReprojectionVirtualization()` so feature destruction never leaves a dead ring game-visible.
8. **Backpressure policy** — packet starvation drops a frame instead of tearing down the worker; hard failures downgrade permanently per session; all worker waits bounded so joins cannot hang.
9. **Resource classification** — `State::Instance().scBuffers` populated with virtual ring resources while virtualized (`ResTrack_Dx12` depends on it).
10. **Locking discipline** — capture-fence waits run outside the wrapper mutex under a dedicated owner ID.
11. **Pacing/timing** — cadence maintained internally via `RecordRealFrame`; documented that packet backpressure is the intended game throttle once `LocalPresent` is bypassed.
12. **Docs/state cleanup** — `AGENTS.md` invariant rewrite, design-doc supersession notes, validation-matrix reset, and `State::Instance().reprojPresenterHwnd` added to the deletion list.
